Yes& Scheduler

Retired v0.7.4 multi-tenant internal & SaaS

Retired on 25 August 2026. It shipped every milestone it set, and then nobody it was built for used it, which is a finish rather than an abandonment. Nothing has been deleted: the code, the design document, the deployment and the links below are all still here, and none of it is maintained any more. Everything past this point describes the project as it stood at its last release, v0.7.4.

A multi-tenant employee-scheduling SaaS. Each client company gets its own isolated organization on the same instance - cross-org access returns 404, never 403, so tenant existence never leaks. Employees sign in with a magic link, set Preferred / Available / Unavailable on a rolling six-week shift window, and request swaps, drops, time off, or open-shift claims. Managers run an auto-fill that rotates through staff (preferred shifts first, then availability, then min-hours), edit cells manually, publish a week, and clear a review queue. Admins manage users, departments, sub-departments, system settings, and an append-only audit log. A super-admin role observes every org, invites admins, and never owns. Built first for an Aquatics department (Lifeguard + Swim Instructor) and architected to host any number of independent companies side-by-side without code changes. Mobile-first - verified at 360px.

v0.7.4 - what's new

Security and concurrency (v0.7.3). Two dependency bumps close CVEs flagged against the old pinned ranges. Three write paths that used to read and then write now do both inside one statement or one transaction, so a failure between the halves cannot leave the schedule in a state no retry reaches: a user's sub-department assignments can no longer be half-replaced, a swapped shift can no longer end up with neither person on it, and an open-shift claim enforces capacity inside the insert rather than in a select the write could race behind. Migration 0012 adds a uniqueness constraint as a database-level backstop and de-duplicates anything an earlier race produced.

Reliability and doc accuracy (v0.7.2). The list endpoint's per-user query is batched and chunked to the database's bind-parameter cap, and migration 0011 adds the composite index the org-scoped audit-log read was always meant to use. The release scripts stopped deleting a git lock before the guard could look at it, which is how a config file got truncated once before, and stopped titling a commit as a release when the version had not moved. The design document now states plainly that six of the seven policy knobs are inert rather than implying all seven work.

Per-seat billing entitlement, onboarding, and demo data (v0.6.0). Migration 0009 adds a per-org billing row (plan, status, seat limit, exempt flag) and a per-user seat-exemption flag. A billable seat is one active, non-exempt member, and an org with no billing row reads as an unlimited trial, so existing orgs needed no backfill. Admins see plan, status, and seats used on Admin Settings; only the super-admin sets plans, seat limits, and exemptions. No payment provider is wired and nothing is paywalled: this is entitlement only. A self-checking "Get started" guide points a new org at its next setup step and hides once configured, and a re-runnable demo seed populates a realistic org for live-flow testing.

A twenty-improvement quality pass (v0.7.0). The SPA code-splits per route, dropping the entry bundle from 539 kB to 423 kB, and the dashboard's next-shift lookup now fans out concurrently instead of walking up to fifteen requests one at a time. Migration 0010 adds the equality-first shifts(sub_department_id, date) index that generate, publish, listing, and export all actually filter on. CSV export neutralizes spreadsheet formula injection in user-controlled display names. An error boundary replaces the white screen on a render error, unknown paths get a real 404 instead of a silent redirect, and org creation is finally audit-logged. GET /api/health reports the applied D1 schema version, every page opens with a skip-to-content link, a page-specific tab title, and the API test suite is up to 139. v0.7.1 was a docs-only pass bringing DESIGN.md back in line with the magic-link world, where there are no passwords to reset.

Stack

Cloudflare Workers + D1 SQLite for the API (Hono routes, schedule auto-fill, org boundary enforcement, notifications, audit log). React 18 + TypeScript + Vite + Tailwind on the SPA, deployed to GitHub Pages. Supabase Auth for magic-link sign-in; the Worker verifies Supabase JWTs against the project JWKS - no passwords stored anywhere. Resend SMTP for transactional email. Single pnpm workspace: apps/web, apps/api, packages/shared. The current milestone is M8, Shift options + holidays.
